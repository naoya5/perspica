## M0 で作るもの（これだけ。M1 以降の機能は作らない）

作る場所: `/Users/naoya/docs/agentic-os/projects/translate-app/app/`（SPEC 17 章の構成）

1. **パッケージ**: `Package.swift`（swift-tools-version 6.0、`platforms: [.macOS(.v26)]`、Swift 6 の言語モード）。ターゲットは `YakuCore`（library、UI なし）、`Yaku`（executable）、`YakuCoreTests`（Swift Testing）。外部の依存なし
2. **`make-app.sh`**: `swift build -c release` → `build/Yaku.app` に包む（`Resources/Info.plist`: `LSUIElement=YES`、`LSMinimumSystemVersion=26.0`、`CFBundleIdentifier=dev.naoya.yaku`、`CFBundleName=Yaku`）→ `codesign -f -s "Yaku Dev"`（ログインキーチェーンにもう作ってある自己署名の証明書。`security find-identity -p codesigning` で "Yaku Dev" が見える。アドホック署名は使わない）。`./make-app.sh install` で `~/Applications/Yaku.app` に置き換えてコピーする
3. **YakuCore**:
   - `PFML3`: SPEC 7.2 のとおりにプロンプトを組み立てる（文脈・訳の履歴 最大 2 組・用語集・言語・文体。`<|plamo:` を原文と文脈から取り除く）
   - `SSEParser`: `data: {...}` 行から `choices[0].text` を取り出す。`data: [DONE]` で終わり。行が途中で切れて届いても正しく扱う
   - `CompletionRequest`: SPEC 7.2 の JSON（`max_tokens` の計算を含む）
   - `EngineClient`: `URLSession.bytes` で SSE を読み、`AsyncThrowingStream<String, Error>` で文字を返す。`Authorization: Bearer`。Task を取り消すと接続を切る
   - `TranslationCleanup`: 末尾に残った `<|plamo:tag|>` / `<|plamo:bos|>` を消す
4. **YakuCoreTests**: 上の 5 つすべてにテスト。PFML3 は、モデルカードの例（`lab/plamo-pdf-translate/models/plamo-3-translate-0.8b-MLX-4bit/README.md` の「PFML3 Prompt Format」以降。glossary・context・history の例）と 1 文字も違わないことを確かめる
5. **エンジンの管理**（`Yaku/Engine/`、SPEC 7.1）:
   - 実行ファイルは `Contents/Helpers/llama-server` → なければ `/opt/homebrew/bin/llama-server`
   - モデルの場所は設定 `modelPath`（UserDefaults）。M0 の既定は `/Users/naoya/docs/agentic-os/lab/plamo-pdf-translate/models/plamo-3-translate-0.8b-GGUF/plamo-3-translate-0.8b-Q4_K_M.gguf`
   - 空き番号（0 番で bind して OS に選ばせる）、起動ごとの乱数の API キー、SPEC 7.1 の引数。`/health` を 200 まで待つ（15 秒で失敗）
   - 使わない時間（既定 600 秒、起動オプション `--engine-idle-seconds N` で変えられる）がたったら止める。アプリの終了時に止める
   - アプリが強制終了されたときに llama-server が残らないように: 起動したエンジンの PID を `~/Library/Application Support/Yaku/engine.pid` に書き、次の起動時にその PID がまだ生きていて、コマンドが自分の起動した llama-server（引数に `--alias plamo-3-translate` と自分の API キーを含む、など確実に見分けられる条件）なら止める。**それ以外のプロセスは絶対に止めない**（ポート 5191 の共通エンジンなど、ほかの llama-server が動いていることがある）
   - ログ: `~/Library/Logs/Yaku/engine.log`（llama-server の出力）、`app.log`（アプリの出来事。時刻つき）
6. **メニューバーのアイコン**（SPEC 4.1）: `NSStatusItem`、SF Symbol `character.bubble`（テンプレート）。左クリックでパネルの開閉、右クリックでメニュー（「管理画面を開く」は M0 では無効の項目でよい / 「一時停止」= エンジンを止める / 「終了」）。エンジン起動中はアイコンをゆっくり明滅
7. **パネルの外側**（SPEC 4.2 の「窓」「見た目」と、「状態」の「空」だけ）:
   - `NSPanel`（borderless + nonactivatingPanel、`canBecomeKey = true`、背景は透明）。起動時に作って隠しておく。位置はアイコンの真下（メニューバーの下端から 6pt）。窓は最大の大きさ（幅 400 + 影の余白 × 高さ 600 + 余白）に固定し、中の形だけを動かす。形の外はマウス操作を下に通す（試作の `hitTest` のやり方）
   - 背景: `glassEffect(.regular, in: .rect(cornerRadius: 24, style: .continuous))`。ガラスの上にガラスを重ねない（SPEC 6.1）
   - 中身は「空」の状態だけ: 上の帯（言語の表示 `自動 → 日本語` は表示だけ、文体の切り替えは見た目と切り替えの動きだけ、ピン、その他のメニュー）、原文の入力欄（プレースホルダーつき。日本語入力ができること）、一番下の 3 つのボタン（`GlassEffectContainer` + カプセル。押しても M0 では何もしない）。高さ 168
   - 開閉: SPEC 4.2 の動き（アイコン側を起点に 0.96 → 1、不透明度、標準のばね。閉じるのは 0.18 秒のイーズ）。Esc・外のクリック・アイコンのクリック・⌃⌥K で閉じる。ピンがオンなら外のクリックでは閉じない。「視差効果を減らす」ならフェードだけ
   - 開いたら原文の欄にフォーカス。前面のアプリは前面のまま（`NSApp.activate` を呼ばない。`.nonactivatingPanel` のまま key にする）
   - パネルを開いたら、エンジンの起動を始める（SPEC 7.1「起動は遅らせる」）
8. **ホットキー**: ⌃⌥K（Carbon の `RegisterEventHotKey`）でパネルの開閉。⌃⌥J・⌃⌥O は M0 では登録しない
9. **起動オプション**（SPEC 15 章のうち M0 の分）:
   - `--demo-surface panel --demo-state empty`（起動したらパネルを開いたままにする）
   - `--demo-quit-after <秒>`
   - `--appearance light|dark`（`NSApp.appearance` を変える。システムの設定は変えない）
   - `--demo-translate "<英文>"`: UI を出さずにエンジンを起動し、`EngineClient` で訳して、訳文と「最初の文字までの秒数・全体の秒数」を標準出力と `app.log` に出して終了する
   - `--engine-idle-seconds <秒>`

## 確かめること（すべて実際に動かして確かめる。画面のロックは解けている）

1. `swift build`・`swift test` が通る（警告もなくす）。`./make-app.sh` が通り、`codesign -dvv build/Yaku.app` の Authority が `Yaku Dev`
2. `--demo-translate "Attention is all you need."` などで 3 つの文を訳し、時間を記録する。終了後に自分の llama-server が残っていないこと（`ps -o pid,command -ax | rg 'alias plamo-3-translate'` などで、自分が起動した PID がないことを確かめる）
3. `--engine-idle-seconds 20` で起動 → パネルを開いてエンジンを起動 → 20 秒後に止まることをログで確かめる
4. 強制終了のあと: アプリを起動してエンジンを立ち上げ、アプリだけを `kill -9 <自分のアプリの PID>` → もう一度起動すると、残ったエンジンが止まる
5. 実画面の撮影: `--demo-surface panel --demo-state empty --demo-quit-after 8` で起動し、パネルの窓を `screencapture -x -o -l <windowID>` で撮る（windowID は `CGWindowListCopyWindowInfo` を使う小さな Swift スクリプト `app/tools/winid.swift` を書いて、プロセス名 `Yaku` の窓から求める）。ライトとダーク（`--appearance`）の 2 枚。加えて、パネルのまわり（幅 600 × 高さ 400、メニューバーを含む）を `screencapture -x -R` で撮った 2 枚。`docs/checks/shots/M0-*.png` に置き、**自分で開いて見た目を確かめる**（ガラスが透けているか、角丸、文字の読みやすさ、メニューバーとの間隔）
6. パネルの開く速さ: ホットキーを受け取ってから `orderFront` が終わるまでの時間を `app.log` に書く（ホットキーは自動で押せないので、`--demo-surface panel` のときの同じ経路の時間を代わりに使ってよい。そう書く）
7. 計測（SPEC 14 章の測り方は `lab/plamo-pdf-translate/notch-app/SPEC.md` 6 章。エンジンを除く）: `.app` の容量、待機中のメモリ（パネルを閉じて 30 秒後の RSS）、待機中の CPU（1 秒おき 10 回の平均）、パネルを開いたままの CPU、エンジンの起動時間、最初の文字までの時間
8. 人が操作しないと確かめられないこと（アイコンのクリック、⌃⌥K、Esc、外のクリック、日本語入力）は、コードとログで経路を確かめるところまでにして「未確認（人の操作が要る）」と書く。マウスやキーを勝手に送るツールは使わない
