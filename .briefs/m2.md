## M2 で作るもの

1. **M1 の直し（先にやる）**
   - Yaku を同時に 1 つしか動かさない（SPEC 7.1）。2 つ目は起動してすぐ終わる。`--demo-*` で出したものも同じ。`--demo-translate` もこの決まりに従う
   - エンジンを見張り役を通して起動する（SPEC 7.1）: `/bin/sh` の小さなスクリプトなどで llama-server を起動し、アプリの PID がなくなったら（`kill -9` されたときも）llama-server を止める。起動時の後片付けは残す
   - 空とエラーの状態では、下の帯のコピーと「管理画面で開く」を出さない。エラーの状態でボタンの下に広い空白を作らない
2. **管理画面**（SPEC 4.4）: `Window` シーン + `NavigationSplitView`。開いている間だけ Dock と ⌘Tab に出す。ほかのウィンドウ（パネル・HUD）とのフォーカスの行き来を壊さない
   - 翻訳: 左右 2 つの欄。toolbar に言語・入れ替え・文体・訳すボタン（`.glassProminent`）。M1 の翻訳の仕組み（`TranslationCoordinator`）をそのまま使う。訳文は 17pt・行間 1.5・文字の出現と光あり
   - PDF: M3 で作る。サイドバーの項目と「PDF の翻訳は次の段階で入ります」の空の画面だけ
   - 履歴: 検索できる一覧と、選んだときの全文。コピー・削除・「用語集に足す」（原文と訳文の一部を選んで足せる簡単な形でよい）。履歴が空のときの文言（SPEC 13 章）
   - 用語集: `GlossaryEntry`（SPEC 11 章）の表。追加・削除・有効の切り替え・並び替え・CSV の読み込みと書き出し。最初に見本（無効）を入れる。**訳すときに有効な項目のうち原文に現れるものを PFML3 の glossary に入れる**（`GlossaryFilter` は M1 にある）。パネル・HUD・管理画面のどの入口でも効くこと
   - モデル: 0.8B / 2B / 8B のカード（大きさ・必要なメモリの目安・状態）。取得（途中から再開できる、SHA-256 を確かめる、進み具合、取り消し）・削除・「使う」。取得の前に PLaMo Community License を表示して同意を求める（同意は覚える）。既存のファイルを選ぶ方法も残す（M0 の `modelPath` の既定のファイル）。使うモデルを変えたらエンジンを起動し直す
3. **設定**（SPEC 4.4 の表）: `Settings` シーン（⌘,）。一般・ショートカット・エンジン・PDF（M3 用の項目は表示だけでよい）・画面翻訳（M4 用、表示だけ）・プライバシー。ショートカットは押して登録する欄を自分で作る（外部の依存なし）。重なったら警告。「ログイン時に起動」は `SMAppService.mainApp`
4. **初回の案内**（SPEC 4.7）: 4 ページ。2 ページ目のモデルは「既存のファイルを使う」と「取得する」の両方
5. **入口をつなぐ**: パネルの「管理画面で開く」・その他のメニューの「管理画面」「設定」、メニューバーの右クリックの「管理画面を開く」「設定…」、パネルの「履歴」ボタン（管理画面の履歴を開く）、⌘N・⌘1〜⌘5（SPEC 12 章）、HUD の ⌘O は M1 のまま
6. **起動オプション**: `--demo-surface manager [--demo-page translate|pdf|history|glossary|models]`、`--demo-surface settings [--demo-tab <名前>]`、`--demo-surface onboarding [--demo-page <1-4>]`、`--data-dir <フォルダ>`（Application Support の代わりにそのフォルダを使い、UserDefaults も別の名前の領域にする。初めてのユーザーとして試すため）

## モデルの取得について
- ネットワークを使ってよいのは Hugging Face（huggingface.co とその転送先）だけ。最初に、2B / 8B の GGUF のリポジトリ名・ファイル名・大きさ・SHA-256 を Hugging Face の API（`https://huggingface.co/api/models/pfnet/...`、ファイル一覧は `/tree/main`。LFS の `oid` が SHA-256）で調べて、カードの数字に入れる。0.8B の GGUF のリポジトリ名も同じく確かめる
- 実際に取得して確かめるのは 0.8B（約 0.57GB）だけ。`--data-dir` で一時のフォルダに落とし、途中で取り消してから再開できることと、SHA-256 が合うことを確かめる。2B / 8B は落とさない。終わったら、その一時のフォルダの GGUF は具体的なパスで消してよい

## 確かめること（すべて実際に動かす。画面のロックは解けている）
1. `swift build`・`swift test` が警告なしで通る。足した YakuCore の部分（CSV の読み書き、SHA-256 の確認、ショートカットの重なりの判定など）にテスト
2. `./make-app.sh install`（Authority=Yaku Signing）
3. **用語集が効く**: 用語集に「Attention → アテンション」を有効で入れ、`--demo-translate` 相当の経路（または管理画面の翻訳）で見出しの "3.2 Attention" と文 "Attention is all you need." を訳す。用語集なしと比べた結果を表にする
4. 同時に 1 つ: 2 つ目を起動したらすぐ終わる（ログ）。見張り役: エンジンを起動した状態でアプリを `kill -9` → 数秒以内に llama-server が止まる（自分が起動した PID で確かめる）
5. 初めてのユーザー: `--data-dir` の新しいフォルダで起動し、初回の案内の 4 ページを撮る。モデルの取得は上のとおり
6. 実画面の撮影（ライトとダーク）: 管理画面の 5 ページ、設定のタブ、初回の案内、M1 の直し（空・エラーの状態のパネル）。`docs/checks/shots/M2-*.png`。**全部自分で開いて見る**: サイドバーと toolbar が macOS 26 の標準のガラスになっているか、自前のガラスを重ねていないか（SPEC 6.1）、文字の大きさと余白
7. 計測（SPEC 14 章。メモリは phys_footprint）: 待機中、管理画面を開いている間、閉じた後（閉じたらメモリが戻るか）
8. 人の操作が要るもの（クリック・キー・ショートカットの登録の欄・ドラッグでの並び替え・ログイン時の起動の切り替えがシステム設定に出ること）は「未確認」と書く。マウスやキーを送るツール、ほかのアプリを動かすことは使わない

## 守ること
- 書いてよいのは `projects/translate-app/app/` と `projects/translate-app/docs/checks/` の中、`~/Applications/Yaku.app`、`~/Library/Application Support/Yaku/`、`~/Library/Logs/Yaku/`、`--data-dir` に使う一時のフォルダ（`$TMPDIR` の下）だけ。SPEC.md・context.md・lab/・リポジトリのほかの場所は変えない（仕様のおかしいところは M2.md に書く）
- 署名は `make-app.sh` のとおり。パスワードのファイルの中身をどこにも書かない
- git の commit・push はしない。有料の API は使わない。ネットワークは上の Hugging Face だけ
- `rm -rf` やワイルドカードでの削除はしない（`make-app.sh` の中の具体的なパスと、上の GGUF は除く）
- 自分が起動したプロセス以外を止めない。`pkill -f` / `killall` は使わない。**終わる前に、自分が起動した llama-server と Yaku が残っていないことを確かめる**（M1 では 1 つ残っていた）
- ほかの llama-server（5191・5192 など）に触らない。システムの設定（外観・アクセシビリティ・ログイン項目など）を確かめるために勝手に変えない。`SMAppService` の登録を試したら、終わる前に登録を外す
- `curl` は hook で止められることがある。HTTP は `python3 -c "import urllib.request; ..."` か、アプリの `URLSession` で
