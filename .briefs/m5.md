あなたはローカル翻訳アプリ「Yaku」（仮称）の段階 M5 を実装する。M0〜M4 は別のスレッドが作り、親（私）がレビューと実画面の撮影まで済ませた。設計・レビューは親が持つ。

## 始める前に
- ユーザーの Yaku（`~/Applications/Yaku.app`）が動いていると、デモが起動できない（1 つしか起動しない作り）。`osascript -e 'tell application id "dev.naoya.yaku" to quit'` で終了してから始め、**終わったら `./make-app.sh install` のあと `open ~/Applications/Yaku.app` で起動し直しておく**
- 撮影と計測の手順書は、既定で一時のフォルダ（`$TMPDIR/yaku-demo-data`）をデータの場所に使う。**本物のデータ（`~/Library/Application Support/Yaku/Yaku.store`）を使う起動はしない**（デモは必ず `--data-dir` か手順書の既定で）
- 画面のロックが解けているか確かめる（`ioreg -n Root -d1 -a | plutil -extract IOConsoleUsers xml1 -o - - | grep -A1 CGSSessionScreenIsLocked` で何も出なければ解けている）。撮影の窓の選び方は `tools/capture-lib.sh`（中身が描かれた窓だけ残す）。`/tmp/winid` と `/tmp/opaque` を `swiftc -O` で作っておく

## M5 でやること

### A. 撮影で見つかった不具合と見た目（各 M*.md の 7 章）
1. 画面の翻訳: 見出しの太さ（太字が普通になる）を元に合わせる。UI の画面で題と説明が 1 ブロックになって狭い幅で読みにくく折り返す件 → SPEC 9 の規則を見直す（案: 行の高さの差が 25% を超えるなら別のブロック、を厳しめに。どう変えたかとテストを書く）。2 段組の読む順（段ごとに上から）。左の小さな灰色の文字（UI 見本のサイドバー）が読み取られない理由を調べる（確からしさ・大きさ・`minimumTextHeight` など）
2. PDF: 図の中の文字が大きくなる（M3 の 6 章「多頭アテンション」）。BabelDOC の設定で抑えられるか調べ、抑えられれば直す。だめなら理由を書く。パネルの「PDF の仕事中」のデモで PDF の行が出ない件（デモだけの問題か本物もか）。設定の PDF タブの「導入済み」のデモが「未導入」と出る件
3. 見た目: 初回の案内の下の大きな空き、モデルのページで開発用のファイルを使っているのに「未取得」「取得する」と出る件（開発用のファイルを使っているとそう書く）、ライセンスのシートの「同意して取得する」を目立つボタンに、管理画面の翻訳の原文の欄の空のスクロールバーの溝
4. M2 からの持ち越し: ライセンスのシートを開いたままだと終了できない疑い。デモ（`--demo-download-gate`）で開き、自分が起動したデモのプロセスに `osascript` の quit を送って確かめる（ユーザーの Yaku には送らない。デモを起動している間はユーザーの Yaku は終了している）

### B. SPEC 14 章の数字をすべて測って直す
- 全部を測り、表にする（`tools/measure-m2.sh`〜`m4.sh` を使い、足りないものは `tools/measure-m5.sh` を作る）
- 分かっている外れ: **エンジンの起動（0.8B）が 2.8〜5.0 秒で、目標の 3 秒を超える**（app.log の `engine ready ... in`）。llama-server の引数（warmup・mmap・ctx・parallel など）と起動の待ち方（ヘルスチェックの間隔）を調べて直す。訳の品質と並列（PDF とパネル）を落とさないこと
- **訳している最中の CPU を 5% 未満にする**（M1 で 11〜13%。光と文字の出現の分。M1.md の 4.1 に経緯）
- 測っても 0.00% になるものは、窓が出ている間に訳が終わっている可能性がある。測る窓と、その間に何が動いているかを確かめてから数字を書く

### C. アクセシビリティ（SPEC 18 の M5）
- VoiceOver: パネル・HUD・管理画面・重ね表示・島の主な部品に名前と役割。読み上げの順
- 視差効果を減らす（光は回転をやめて明滅に。M1 で分岐は入れてある）・透明度を下げる（ガラスを不透明の面に）・コントラストを上げる（縁と文字）。**システムの設定は変えない**。代わりに、起動オプション（例: `--demo-reduce-motion`・`--demo-reduce-transparency`・`--demo-increase-contrast`）でその見た目を出せるようにし、撮る

### D. アプリのアイコンと README
- アイコン: SPEC 6 章の考え方で。Icon Composer の `.icon` を手で書けるか（`xcrun actool` で `Assets.car` にできるか）を試し、だめなら `.icns` にする。絵は CoreGraphics か SVG を自分で描く（有料の画像生成は使わない）。メニューバーのアイコンとの関係も書く
- `projects/translate-app/README.md`: 何か・入れ方（`make-app.sh install`）・使い方（ショートカット）・権限・データの場所・作り直し方。短く

### E. 4 通りの撮影（SPEC 15）
- 明るい背景と暗い背景 × ライトとダーク。**壁紙は変えない**。代わりに、ガラスの後ろに置く背景の窓を出す起動オプション（例: `--demo-backdrop light|dark`。画面いっぱいの写真風のグラデーションか模様）を足し、パネル・HUD・島・重ね表示の帯を範囲で撮る（窓だけ撮るとガラスの後ろが空で灰色になるため）
- 撮った画像は自分で開いて見て、気づいたことを書く
