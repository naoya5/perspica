## 2. ビルド・テスト・起動の方法

```sh
cd projects/translate-app/app
swift build                 # 警告なし
swift test                  # 35 テスト
./make-app.sh               # build/Yaku.app を作って署名
./make-app.sh install       # ~/Applications/Yaku.app に置く
```

`--demo-translate` 以外は画面を出すので、`--demo-quit-after` を付けて試す。

```sh
./build/Yaku.app/Contents/MacOS/Yaku --demo-surface panel --demo-state empty --demo-quit-after 8
./build/Yaku.app/Contents/MacOS/Yaku --demo-translate "Attention is all you need."
./build/Yaku.app/Contents/MacOS/Yaku --demo-surface panel --demo-state empty --engine-idle-seconds 20 --demo-quit-after 40
```

## 3. 確認の結果

### 3.1 ビルド・テスト・署名

| 項目 | 結果 |
|---|---|
| `swift build`（debug / release、クリーンビルド） | 通る。警告 0、エラー 0 |
| `swift test` | 35 テスト / 5 スイート、すべて通る |
| `./make-app.sh` | 通る。`codesign --verify` も通る |
| `codesign -dvv build/Yaku.app` の Authority | `Yaku Signing`（下記 4.1 を参照） |
| `CFBundleIdentifier` | `dev.naoya.yaku` |
| `make-app.sh install` → `~/Applications/Yaku.app` | 通る。署名を保ったまま起動できる |

PFML3 のテストは、モデルカードの「PFML3 Prompt Format」以降の例（素の依頼・用語集・文脈・plain・polite・訳の履歴・全部入り）と **1 文字も違わない**ことを確かめている。

### 3.2 `--demo-translate` で 3 文（エンジンは起動ごとに新しく立てる）

| 原文 | 訳文 | エンジンの起動 | 最初の文字 | 全体 |
|---|---|---|---|---|
| Attention is all you need. | 注目さえあれば十分です。 | 1.91 秒 | 0.038 秒 | 0.076 秒 |
| The quick brown fox jumps over the lazy dog. | 素早い茶色のキツネが、のんびりした犬を飛び越えます。 | 1.48 秒 | 0.287 秒 | 0.378 秒 |
| Please open the project dashboard and check the active tasks. | プロジェクトダッシュボードを開き、進行中のタスクを確認してください。 | 1.68 秒 | 0.035 秒 | 0.106 秒 |

- 終了後、`ps -o pid,command -ax | rg 'alias plamo-3-translate'` で自分のエンジンは残っていない。`engine.pid` も消えている。
- 文脈も用語集も渡していないので、1 文目は「注目さえあれば十分です。」になった。SPEC 5.2 が挙げている 0.8B の弱点（"Attention" → 「注意」）がそのまま出ている。M1・M2 の用語集と文脈で直す対象。

### 3.3 使わない時間でエンジンが止まる（`--engine-idle-seconds 20`）

`--demo-surface panel` でパネルを開いた → エンジンが立つ → 20 秒後に止まる、をログで確認。

```
panel open (demo-surface) 1.5ms from action to orderFront
engine start pid=30426 port=59057 ...
engine ready pid=30426 in 1.67s
engine idle for 20s; stopping
engine stop pid=30426
```

既定は 600 秒（SPEC 7.1 の 10 分）。

### 3.4 強制終了のあとの後始末

| 手順 | 結果 |
|---|---|
| アプリを起動してエンジンを立てる | app pid=69581 / engine pid=69613（port 61200） |
| アプリだけを `kill -9 69581` | エンジン 69613 は残る（期待どおり）。`engine.pid` に記録が残る |
| もう一度起動する | `stopping leftover engine pid=69613 port=61200` → `stopped` → 新しいエンジン 69794 を起動 |

- 見分けは「コマンド行に `llama-server` と `--alias plamo-3-translate` と自分の API キーと自分のポートが全部ある」ときだけ止める。
- 同時に動いていた別の `llama-server`（`-hf Qwen/Qwen3-4B-GGUF ... --port 5192`、pid 50311）は最後まで触っていない。

| 項目 | 目標 | 実測 | 判定 |

| 同じときの private footprint | — | 21 MB | （参考） |

## 4. 仕様との違い・できなかったこと

### 4.1 署名の証明書

SPEC 16 章はログインキーチェーンの「Yaku Dev」と書いているが、この環境では `codesign -s "Yaku Dev"` が**承認のダイアログが出ないまま固まる**（キーチェーンはロックされていない。`--timestamp=none` や `--keychain` を明示しても同じ。小さなファイル 1 つでも止まる）。親スレッドが開発専用のキーチェーン `~/Library/Keychains/yaku-dev.keychain-db` と証明書「Yaku Signing」を用意したので、`make-app.sh` はそちらで署名する（承認なしで 0.4 秒）。`codesign` には `timeout 30` を付け、固まったら失敗として扱う。SPEC 16 章の記述は親スレッドが直す。

パスワードのファイルは `~/Library/Application Support/Yaku/dev-signing/pass` にあり、`make-app.sh` が `security unlock-keychain` に読ませるだけ。中身はどこにも書かない。

### 4.2 `Package.swift` の書き方

SPEC 16 章は swift-tools-version 6.0 と `platforms: [.macOS(.v26)]` を求めているが、`.v26` は PackageDescription 6.2 以降でしか使えず、6.0 のマニフェストでは弾かれる。tools-version を 6.0 のままにするため、同じ意味の `.macOS("26.0")` で書いた（展開後の対象は同じ macOS 26.0）。

### 4.3 待機中のメモリが目標を超えている

88MB 前後で、目標の 60MB を超える。調べたこと:

- ガラス（`glassEffect` / `GlassEffectContainer`）を外した版 → RSS 86.9MB。**ガラスは原因ではない**
- `NSStatusItem` を消した版 → RSS 84.8MB。**アイコンも原因ではない**
- private footprint は 21MB しかないので、RSS の差は共有フレームワーク（SwiftUI / AppKit 一式）の常駐分が大きい

原因は特定できていない。M1 で測り直して、必要なら切り分けを続ける。

### 4.4 その他

- パネルの影は SwiftUI の `.shadow` で付けている（窓は透明・`hasShadow=false`）。SPEC 4.2 の「影はシステムの窓の影」とは違うやり方。M1 で見直す。
- `--demo-state empty` は受け取るが、M0 には「空」の状態しかないので値は使っていない。
- パネルの高さは 168 固定（SPEC 4.2 の「高さは中身に合わせて 168〜600」は M1）。
- 窓は最大の大きさ（幅 400 + 影の余白 32×2 = 464、高さ 600 + 余白 = 632）で固定し、中の形だけを動かす。形の外は `hitTest` でマウスを下に通す。
- 「管理画面を開く」は無効の項目、「その他（`ellipsis`）」「言語の切り替え」は見た目だけで、押しても何もしない（SPEC の M0 の範囲どおり）。

## 5. M1 に向けて気づいたこと

- **原文の欄のスクロールバー**が常に見える。`TextEditor` の見た目を直す必要がある。
- **0.8B は文脈と用語集がないと弱い**。「Attention is all you need.」が「注目さえあれば十分です。」になった。M1 の文脈（5.2）と M2 の用語集が効くはず。
- **最初の文字が速い**（0.035〜0.287 秒）。SPEC 14 章の 300ms に余裕があるので、文字の出現（140ms）や光を足しても間に合いそう。
- **パネルの高さを動かす仕組み**がまだ無い。窓は最大固定なので、形の高さを状態で変える部分を M1 で作る。
- エンジンの起動が 1.5〜2.3 秒なので、「準備しています…」の表示（SPEC 4.2）は M1 で必要になる。

親の側でやり直して確かめたこと:

| 項目 | 結果 |
|---|---|
| `swift test` | 35 テスト / 5 スイート、すべて通る |

| 撮影 4 枚 | 位置・角丸・ガラス・ライトとダークの読みやすさは良い |

判断:
- **メモリは合格とする**。SPEC 14 章の測り方を phys_footprint（アクティビティモニタの「メモリ」と同じ値）に改めた。RSS には SwiftUI / AppKit の共有ページが入るので、参考値として残す
- **ガラスの重ね方**: パネルの上のカプセルのボタンと文体の切り替えはガラスのままでよい。SPEC 6.1 に例外として書いた（4.2 の 7 と 6.1 が食い違っていたのは仕様の誤り）
- **影**: SwiftUI の `.shadow` でよい。SPEC 4.2 を改めた
- `Package.swift` の `.macOS("26.0")` はそのままでよい
- M1 で直すこと: 原文の欄のスクロールバーが常に見える。空の状態の原文の欄が広すぎる（何もないところが目立つ）。エンジンが途中で落ちたときに 1 回だけ起こし直す処理（SPEC 7.1）がまだ無い
- `around-*.png` に、ログインキーチェーンの鍵を使おうとして止まった codesign のパスワードの窓が写っている。もう閉じていることを確かめた
