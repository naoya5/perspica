### 3.2 用語集が効く（SPEC 5.2）

`--data-dir` の新しいフォルダで起動し、`GlossaryEntry` の見本のうち **Attention → アテンション** だけを有効にして、見出しの `3.2 Attention` と文 `Attention is all you need.` を訳した。`--demo-glossary off` が用語集を外した場合。

| | 用語集なし | 用語集あり |
|---|---|---|
| ログの `glossary=` | 0 | 1 |
| 訳文（`--demo-translate`） | 3.2 **注意**<br>必要なのは**注意**だけです。 | 3.2 **アテンション**<br>必要なのは**アテンション**だけです。 |
| 訳文（管理画面の翻訳） | — | 3.2 **アテンション**<br>必要なのは**アテンション**だけだ。 |
| 訳文（パネル） | — | 3.2 **アテンション**<br>必要なのは**アテンション**だけだ。 |
| 訳文（HUD、`Attention is all you need.`） | — | **アテンション**さえあれば十分だ。 |

**入口ごとに確かめた。** どの入口も `TranslationCoordinator.run(surface:...)` の同じ 1 本を通り、そこが `GlossaryFilter.relevant(store.enabledGlossaryPairs(), in: text)` で絞っている。ログの `glossary=` がそれを示す。

```
translate start id=233223DB surface=panel   chars=40 chunks=1 ... glossary=1 model=0.8b
translate start id=407D01CB surface=manager chars=40 chunks=1 ... glossary=1 model=0.8b
translate start id=1ADD357D surface=hud     chars=26 chunks=1 ... glossary=1 model=0.8b
```

管理画面の 2 回目は `cache=hit` になった。キャッシュのキーに用語集が入っているので、用語集を変えれば外れる（M1 の `CacheKey` のまま）。

用語集の見本は 6 件（`Transformer → Transformer`、`Attention → アテンション`、`self-attention → 自己アテンション`、`encoder → エンコーダ`、`decoder → デコーダ`、`BLEU → BLEU`）で、**すべて無効**の状態で入る（`ZENABLED=0` を `sqlite3` で確認した）。

見張りは `flock(LOCK_EX|LOCK_NB)`。プロセスがどう終わってもカーネルが外すので、pid ファイルの古さを見る必要がない。`--demo-*` も `--demo-translate` も、`applicationDidFinishLaunching` の一番最初（ストアもエンジンも触る前）で判定する。ロックは `--data-dir` でも標準の場所（`~/Library/Application Support/Yaku/Yaku.lock`）に置くので、デモの 2 つが同時に立つことはない。

### 3.4 見張り役（SPEC 7.1）

エンジンを起こした状態で**アプリだけ**を `kill -9` した。

```
engine start shell=27019 port=53920 model=.../plamo-3-translate-0.8b-Q4_K_M.gguf (PLaMo 3 Translate 0.8B（開発用のファイル）)
engine start server=27020 watchdog=785 bytes
engine ready server=27020 in 1.05s

（ここで kill -9 27017）

t=1s server=gone shell=gone
```

1 秒以内に llama-server も見張り役の `/bin/sh` も消えた。見張り役のスクリプトは、llama-server を起こしてその pid を書き、0.5 秒ごとにアプリの pid を見て、いなくなったら `SIGTERM` → 20 秒待って `SIGKILL` する。自分が `SIGTERM` を受けたときも同じ後片付けをする。

### 3.5 置き去りのエンジン（SPEC 7.1 の起動時の後片付け）

アプリと見張り役を**同時に** `kill -9` して、llama-server だけが残る状態を作った。次の起動が自分のものだけを止める。

```
（llama-server 74586 が親なしで残っている）

stopping leftover engine pid=74586 port=61037
leftover engine pid=74586 stopped
leftover engine pid=74585 is gone
```

見分けは M0・M1 と同じで、コマンド行に `llama-server` と**自分の API キーと自分のポート**が全部あるときだけ止める。ほかの llama-server には触らない。

**途中で見つけて直したこと**: 見張り役だけを `kill -9` すると、アプリは `terminationHandler` で「エンジンが終わった」と受け取り、記録（`engine.pid`）を消してしまう。そのあとアプリを止めると、llama-server が誰にも知られずに残っていた。`childExited` で、自分が止めたのではないときは**残っている llama-server をその場で止め、記録も残す**ように直した。直したあとは、見張り役だけを殺しても llama-server は 1 秒以内に消える。

### 3.6 0.8B の取得・取り消し・再開・SHA-256（SPEC 7.5）

`--data-dir` の新しいフォルダに、実際に Hugging Face から落とした。

| 手順 | 結果 |
|---|---|
| 取得を始めて 4 秒で取り消す | `download cancel at 9137656 bytes`。`models/` に `.partial` が 9,137,656 バイト残る |
| もう一度「取得する」（再開） | `download start ... from=9137656`（`Range: bytes=9137656-`）。残りだけ落ちる |
| 完了 | `download finished 573123200 bytes; checking SHA-256` |
| SHA-256 | `download verified ... sha256=923b2f28a9856de1b8b3b610a7e59ded0b14d007466fd5dd526e6a9ecaadafdd` |
| 別の道具で確かめる | `shasum -a 256` も同じ値 |
| 置き場所 | `models/plamo-3-translate-0.8b-Q4_K_M.gguf`（573,123,200 バイト）に移る。`.partial` は残らない |
| ライセンスに同意していない状態で取得を押す | **取得が始まらない**（`models/` が空のまま）。シートが出るだけ |
| 終わったあと | その一時フォルダの GGUF は具体的なパスで消した |

落としたのは 0.8B だけ。2B / 8B は落としていない。

**カードの数字は Hugging Face の API から取った**（`https://huggingface.co/api/models/<repo>/tree/main`。LFS の `oid` が SHA-256）。ローカルの 0.8B のファイルを実際にハッシュして `oid` と一致することも確かめた。

| | リポジトリ | ファイル | 大きさ | SHA-256（先頭 8 字） |
|---|---|---|---|---|
| 0.8B | `pfnet/plamo-3-translate-0.8b-GGUF` | `plamo-3-translate-0.8b-Q4_K_M.gguf` | 573,123,200 | `923b2f28…` |
| 2B | `pfnet/plamo-3-translate-2b-GGUF` | `plamo-3-translate-2b-Q4_K_M.gguf` | 1,807,199,392 | `f36d0813…` |
| 8B | `pfnet/plamo-3-translate-8b-GGUF` | `plamo-3-translate-8b-Q4_K_M.gguf` | 5,280,442,080 | `47a04e86…` |

カードには Q2_K / Q3_K_M / Q4_0 / Q4_K_M の 4 つがある。llama.cpp で素直に動いてモデルカードも勧めている **Q4_K_M** をカタログに載せた。

### 3.8 撮影（**未撮影。画面がロックされていた**）

**撮れていない。** 作業をしている間ずっと `CGSSessionScreenIsLocked = 1` で、`screencapture -x -o -l <窓ID>` は「could not create image from window」で失敗した。ロック中は窓が合成されないため。**撮った 1 枚も無い。目で見た画面も無い。**

親が 1 回で全部撮れるように `tools/capture-m2.sh` を用意した。ロックを外して走らせれば、`docs/checks/shots/M2-*.png` に次の 40 枚が出る。

|---|---|---|
| manager | 16 | 翻訳（訳し終わった状態）・PDF・履歴・用語集・モデル（× ライト／ダーク）、ライセンスのシート（シートは独立した窓なので、管理画面と 2 枚になる。`M2-manager-license-<外観>.png` が管理画面、`-2` がシート） |

スクリプトは最初にロックを見て、ロック中なら走らずに止まる。窓は `screencapture -l <窓ID>` で窓ごとに撮るので、サイドバーと toolbar は macOS 26 の標準のガラスがそのまま写る（`ImageRenderer` では写らない。SPEC 15）。

**M3 のスレッドから（2026-11-07）**: M3 のコードに手を入れる前に、もう一度ロックを確かめた（`ioreg -n Root -d1 -a | plutil -extract IOConsoleUsers xml1 -o - - | grep -A1 CGSSessionScreenIsLocked`）。**まだ `true` だった。** そのあと M3 の作業中も何度か確かめたが、最後まで `true` のままだったので、`tools/capture-m2.sh` と `tools/measure-m2.sh` は走らせていない。**この 40 枚と CPU は今も未確認のまま。** M3 側は `tools/capture-m3.sh`（30 枚）と `tools/measure-m3.sh` を用意した（[M3.md](M3.md) 3.9）。ロックが解けたら **M2 → M3 の順**に走らせるとよい。

**`ImageRenderer` での代用はしていない。** 管理画面・設定・初回の案内はどれも `NavigationSplitView` / `TabView` / `Form` で、中身は AppKit の窓に載っている。`ImageRenderer` はそれを合成しないので、写っても実際の見た目とは別物になる。**親が実画面を見るまで、見た目の判断は何もできていない**（親が特に見てほしいと言っていた「サイドバーと toolbar が標準のガラスか」「自前のガラスを重ねていないか」「文字の大きさと余白」は、コードの上では 3.10 のとおり）。

**CPU は計測できていない。** 画面がロックされていると描画が止まるので、どの状態でも `0.00%` になり、意味のある数字にならない（訳している最中でも 0.00% だった）。SPEC 14 章は「画面のロックを解いた状態で測る」としているので、ロック中の数字は載せない。`tools/measure-m2.sh` を用意してある。

## 4. 仕様との違い・できなかったこと

### 4.1 画面がロックされていて、撮影と CPU の計測ができなかった（一番大きい）

作業を始めてすぐ（1 枚目の撮影を試した時点）から、この Mac の画面は `CGSSessionScreenIsLocked = 1` だった。**M1 の撮影はできている**（`M1-panel-*.png` はロックが解けているときのもの）ので、M2 の作業中に誰かが画面をロックしたことになる。親に尋ねたところ「ロックが解けるのを待たずに進め、撮影と CPU の計測は後回しにして、仕組みだけ用意しておく」という指示だったので、そうした。

できなかったこと:

- 40 枚の撮影（3.8）。**1 枚も撮れていない**
- SPEC 14 章の CPU の計測（待機中・パネル・光・訳している最中・管理画面）。ロック中はどれも `0.00%` になるので、意味のある数字にならない

できるようにしたこと:

- `tools/capture-m2.sh`（40 枚を 1 回で、ライトとダーク、群を選べる、ロック中は走らない）
- `tools/measure-m2.sh`（SPEC 14 章の計測。管理画面の開閉は `--demo-close-after` で人の操作なしに）

### 4.2 ライセンスのシートが出ていると終了が完了しない（画面ロック中の観測）

管理画面の「モデル」でライセンスのシートを出したまま `NSApp.terminate` すると、`applicationShouldTerminate` が**呼ばれず**、`applicationWillTerminate` も走らず、アプリが終わらない（main thread は普通のイベントループで待っていた）。シートが無いときは同じ経路で問題なく終わる。**画面がロックされているせいなのか、シートのせいなのかは切り分けられていない**（ロックが解けたらもう一度見る）。切り分けの材料として、`applicationShouldTerminate` でシートを閉じて `.terminateNow` を返すようにしてあり、デモの `--demo-quit-after` は先にシートを閉じてから終わる。

**M3 のスレッドから（2026-11-07）**: 切り分けはできていない。**画面が最後までロックされていた**ので、シートを出したまま終了する操作を人なしで再現できないため（`--demo-quit-after` は先にシートを閉じるので、この経路を通らない）。M3 では、PDF の仕事をしている最中に `--demo-quit-after` で終わる経路（`pdfQueue.stopSynchronously()` が worker を止めてから終わる）を何度も通したが、**シートが出ていない状態では問題なく終わった**（M3.md 3.5）。

### 4.3 `--data-dir` のときは設定を JSON に置く

SPEC 11 は設定を `UserDefaults` としている。`--data-dir` は「初めてのユーザーとして試す」ためのものなので、`UserDefaults` を使うと `~/Library/Preferences/dev.naoya.yaku.plist` を汚してしまい、そのあとの普通の起動に影響が残る。そこで `--data-dir` のときだけ、そのフォルダの中の `settings.json` を使う（`AppSettings` の裏側が入れ替わる）。設定の持ち方は `AppSettings` の 1 か所に閉じてある。

### 4.4 ⌘1〜⌘5 は「管理画面が前に出ているとき」だけ効く

SPEC 12 は管理画面のショートカットとしているので、メニューの命令として作った。したがって、ほかのアプリが前に出ているときは効かない。パネルや HUD は非アクティブの窓なので、そこにフォーカスがあるときも効かない。**これは仕様の読み方どおりだと考えているが、実機での確かめは未確認（3.11）。**

### 4.5 PDF のページは置き場所だけ

SPEC 4.4 は PDF のページにドロップ先と処理の一覧を書いているが、SPEC 18 章の段階では M3。M2 では「PDF の翻訳は次の段階で入ります。」の 1 行だけにした。

## 5. 気づいたこと・仕様に足したほうがよさそうなこと

- **撮影と計測は「画面のロックを解いた状態」が前提**（SPEC 15・14 章）。ロックされると `screencapture -l` が失敗するだけでなく、**アプリが描かれないので CPU も測れない**。段階の確認を始める前にロックを外しておく、と 15 章に書いておくとよい
- **窓を閉じてもメモリは戻らない**（3.9）。管理画面を一度開くと、待機中は 30MB ではなく 39MB 前後になる。14 章の「待機中のメモリ」の測り方（いつ測るか）を決めておくとよい
- **8B は 5.28GB + 作業領域で、メモリの目安は約 5.8GB**。16GB の Mac だと他を閉じないと苦しい。カードの「必要なメモリ」に注意書きを足すかは親の判断
- カードの「速さ」は、モデルカードにこの 3 つの大きさの速度の数字が無いので、**「速い／標準／おそい」という定性**にした。数字を出すなら実測が要る（M2 の範囲外）
- SPEC 4.4 の「必要なメモリ」は、重み + 約 0.54GB（16k 文脈の KV キャッシュと llama.cpp の作業領域）としている。実測で裏を取ってはいない
- **用語集は入口をまたいで効く**（3.2）。パネル・HUD・管理画面の 3 つで同じ結果になった。キャッシュのキーにも入っているので、用語集を変えると古い訳は使われない
- M1 から持ち越しの「訳している最中の CPU 11〜13%」は、管理画面の翻訳でも同じ仕組みを通る。M2 では測れていない（4.1）
- 見張り役を入れたことで、**アプリを `kill -9` しても llama-server が残らなくなった**（3.4）。M1 のレビューで見つかった置き去りは、同時に 2 つ動かせることが原因だったので、3.3 の `flock` とあわせて塞がっている
