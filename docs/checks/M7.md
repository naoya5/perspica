# M7 — 設定・管理ウィンドウの見た目の質を上げる

対象は**設定ウィンドウと管理ウィンドウの 2 つだけ**。土台は `0ae8cad`。
パネル・HUD・重ね表示・島・オンボーディングは触っていない。動作・文言の意味・
ショートカットは変えていない。

**この記録で一番大事なこと**: 見た目はコードとテストで完結する範囲まで直した。
**画面ロックのため、`screencapture` を伴う撮影と、VoiceOver の実画面での前後比較は
できていない**（6 章）。窓の高さとタブ切り替えの resize は、画面が要らない計測
（アプリ自身のログと、一時的な計測コード）で前後を比べて確かめた（3.1）。
撮影用の `tools/capture-m7.sh` は書いてあり、ロックを解けばそのまま走る。

## 1. この milestone で利用者に何が変わるか

- **設定**: タブを切り替えると、窓の高さが内容に合わせて変わる。短いタブ
  （画面翻訳・プライバシー）で下半分が空かない（3.1）。
- **設定**: 全 6 タブが「見出し + カード + 説明文」の同じ作りになる（3.2）。
- **設定**: 画面翻訳のスライダーが窮屈でなくなる（3.3）。
- **管理 翻訳**: 原文と訳文がそれぞれカードになり、言語の向き `EN → JA` が
  ヘッダに出る。訳す（主役）とコピー（副）の格がはっきり分かれる（4.1）。
- **管理 履歴**: 行に `EN → JA` と「3 分前」が出る。詳細ペインに日時とカードが入る（4.2）。
- **管理 用語集**: 右上が「読み込む」「書き出す」の**文字つき**になり、似た 2 つの
  矢印で迷わなくなる（4.3）。
- **管理 モデル**: 状態が 1 種類のバッジ（使用中 / 取得済み / 取得中 42% / 未取得 /
  途中まで / 開発用）にそろう（4.4）。
- **管理 PDF**: ドロップ領域がドラッグ中はっきり変わる（破線 → アクセントの実線）。
  失敗行は 1 行に収まり、全文は「詳細」で見られる（4.5）。
- **管理 サイドバー**: 標準の `.sidebar` 素材になり、下のエンジン状態に色の点が付く（4.6）。

## 2. A: 共通の素材とトークン

新しく 2 つのファイルを足した。どちらも設定と管理だけで使う。

- `Sources/Yaku/Design/Design.swift`
  - `Design.Space`（4 / 8 / 12 / 16 / 20 / 24）、`Design.Radius`（card 12 / well 16 /
    field 8）、`Design.Font`（caption 11 / label 12 / body 13 / sectionTitle 15 /
    translation 17）。SPEC 6.3・6.4 の値を 1 か所にまとめた。
  - `designCard()`: 設定と管理の共通のカード面。塗りは**システムの `.quaternary`**
    だけ（自前の色を足さない）。「コントラストを上げる」のときだけ 1px の縁を足す。
  - `DesignSection`: 見出し + 説明 + 中身。管理のスクロール面で使う。
  - `DesignBadge`: 状態を表す 1 種類のカプセル。`DesignBadge.Tone` で色を選ぶ。
  - `DesignLanguageDirection`: `EN → JA`。VoiceOver には「英語 から 日本語」と読ませる。
- `Sources/Yaku/Design/WindowSizing.swift`
  - `SettingsWindowSizer`: 窓の高さを内容に合わせる（3.1）。
  - `measureContentHeight()`: 内容の高さを測る。

**標準の素材を優先した**。サイドバーは `.listStyle(.sidebar)`、設定は `Form` の
grouped スタイル、カードは `.quaternary`。**自前のガラス風の塗りは足していない**
（SPEC 6.1: 大きな面にガラスを重ねない）。ガラスはシステムの（サイドバー・toolbar・
`.glassProminent` のボタン）だけ。

`RelativeTime`（「3 分前」）だけは `YakuCore/RelativeTime.swift` に置いた。週の境目は
色ではなくロジックなので、テストで押さえられるほうがよい（5.3）。

## 3. B: 設定

### 3.1 タブごとに窓の高さが変わる

**前**: 6 タブとも **504 × 405**（`winid` の実測）。窓の高さが一番大きいタブに
固定されていた（プライバシーは下 6 割が空、PDF は逆に足りずスクロールバーが出ていた）。
**後**: タブの内容の高さになる。値はアプリ自身のログ（`settings: window …`）から。
ロック中は窓が画面外にあり `winid` の値が古くなるため、**後はログの値を正**とした。

| タブ | 前（`winid`） | 後の窓の外枠 | うち内容 |
|---|---|---|---|
| 一般 | 504×405 | 560×534 | 446 |
| ショートカット | 504×405 | 560×445 | 357 |
| エンジン | 504×405 | 560×515 | 427 |
| PDF | 504×405 | 560×554 | 466 |
| 画面翻訳 | 504×405 | 560×378 | 290 |
| プライバシー | 504×405 | 560×384 | 296 |

外枠と内容の差は **88pt で一定**（タイトルバーとタブバー。窓は full-size の内容表示なので、
この 88 は内容の**上に重なる**ぶん）。つまり後は「内容 + 88」。

仕組み（`SettingsWindowSizer`）:

1. `Form` の grouped スタイルには**固有の高さがある**（測って確かめた。一般 319 /
   プライバシー 106）。`TabView` も選択中のタブの高さを返す（319 + タブバー 30 = 349）。
2. `TabView` に `.fixedSize(horizontal: false, vertical: true)` を掛けると、窓いっぱいに
   伸びず**内容の高さ**になる。その高さを `GeometryReader` で測る。
3. 測った高さに 88（`safeAreaInsets.top`）を足した値を窓の外枠にし、**上端を固定**して
   下へ伸ばす。タブの切り替えは `animate: true`。
4. 最初の測定は 2 回届く（シーン自身のパス → タブのパス）。両方当てると開いた瞬間に
   小さく跳ねるので、**50ms 待って落ち着いた高さだけ**を当てる。

**確かめたこと（画面を使わずに）**: ログのとおり、6 タブで 534 / 445 / 515 / 554 / 378 /
384 と別々の高さになる。**開いたあとのタブ切り替えでも窓が縮む**ことも確かめた
（一時的に 3 秒後にプライバシーへ切り替えるコードを入れて計測 → 一般 560×534 のあと
プライバシー 560×384 に `animated yes` で変わった。確認後にそのコードは外した）。

窓は前から**リサイズできなかった**（`styleMask` に `.resizable` が無い。1 度だけ
調べるコードを入れて、ログに出ないことで確認した）。触っていない。ユーザーが引き伸ばして
「下半分が空く」状態を作ることはできない。

**確かめられなかったこと**: 切り替えの動きの見た目（滑らかさ）は撮影が要る。数字だけ。

### 3.2 見出し + カード + 説明文

`Form` の `Section` に見出し（`header`）と説明（`footer`）を付けた。カードは grouped の
標準の面。6 タブの見出し:

| タブ | 見出し |
|---|---|
| 一般 | 起動 / 翻訳 / 動作 |
| ショートカット | キー / 重なり（あるとき）/ パネルの中 |
| エンジン | モデル / 停止 / 状態 |
| PDF | PDF ワーカー / 出力 / 開発用 |
| 画面翻訳 | 読み取り / 重ねる文字 |
| プライバシー | 履歴 / 消去 |

これまでカードの中に小さな文字で置いていた説明文は、`Section` の `footer` へ移した
（macOS の設定の作法。見出し・カード・説明の 3 段がそろう）。

### 3.3 スライダーの値ラベル

前は「左に名前、右に細いスライダー、その右に『元の 70%』」が 1 行に並び、窮屈だった。
後は**名前と値を上の行**（値は右寄せ・`monospacedDigit`）、**スライダーは下の行**で
全幅。macOS の Dock の大きさなどと同じ形。

### 3.4 主役のボタンは 1 画面に 1 つ

設定に `.glassProminent`（青）のボタンは**無い**（前も後も 0）。管理では翻訳の「訳す」
だけが `.glassProminent`、コピーは**文字つきの副ボタン**（`.borderless`）にした（4.1）。

## 4. C: 管理

### 4.1 翻訳

- 原文と訳文を**別々のカード**にした（`.quaternary` の面）。白い大判の紙 1 枚ではなく、
  同じ道具の 2 つの面に見える。
- 訳文のヘッダに `DesignLanguageDirection`（`EN → JA`）を置いた。
- 「訳す」だけが `.glassProminent`。コピーは `Label("コピー", systemImage: "doc.on.doc")`
  の副ボタンで、押すと「コピーしました」に変わる。VoiceOver の名前は前と同じ
  「訳文をコピー」に固定した（`accessibilityLabel`）。

### 4.2 履歴

- 行の上段を `入口のアイコン · EN → JA · 3 分前` にした。時刻は相対（`RelativeTime`）。
- 詳細ペイン: 上に `EN → JA` と**絶対の日時**、本文は原文・訳文それぞれカードに。
  余白は `Design.pagePadding`、文字は `Design.Font` にそろえた。

### 4.3 用語集

右上の 2 つのボタンに**文字**を付けた（`Label` に `.labelStyle(.titleAndIcon)`）。
前は `CSV を読み込む` / `CSV を書き出す` というラベルだったが、toolbar が
アイコンだけに畳んでいたため 2 つの矢印が同じに見えていた。いまは「読み込む」
「書き出す」が文字で出る。マウスを乗せると CSV の説明が出る。

### 4.4 モデル

状態の見せ方を `DesignBadge` 1 つに統一した:

| 状態 | バッジ | 色 |
|---|---|---|
| 使用中 | 使用中（`checkmark.circle.fill`） | アクセント |
| 取得済み | 取得済み（`checkmark.circle`） | 緑 |
| 取得中 | 取得中 42%（`arrow.down.circle`） | アクセント |
| 未取得 | 未取得（`circle.dashed`） | 副色 |
| 途中まで | 途中まで（0.3 GB）（`pause.circle`） | 橙 |
| 開発用 | 開発用のファイルを使用中（`hammer`） | 橙 |

文言は前と同じ（`取得中` だけ % が付く）。バッジのアイコンは `accessibilityHidden` なので、
VoiceOver の名前は文字だけのまま。

### 4.5 PDF

- ドロップ領域: ふだんは**破線**、ファイルが乗ると**アクセント色の実線（2px）+ 薄い塗り +
  アイコンが `arrow.down.doc.fill` + 文字が太字**に変わる。`scaleEffect` も 1.02。
- 失敗行: 赤い文は `lineLimit(1)` + 中央省略。右に「詳細」ボタン。押すとポップオーバーに
  全文（選択可）。デモの失敗行に**長いワーカーのエラー**（`ModuleNotFoundError: No module
  named 'babeldoc'（…）`）を入れたので、撮影すれば切れ方が見える。

### 4.6 サイドバー

- `List` に `.listStyle(.sidebar)`。選択行が macOS 26 の標準の丸い選択になる。
- 下のエンジン状態: 色の点（動作中=緑 / 起動中=橙 / 失敗=赤 / 停止中=副色）+「エンジン」
  + 状態の言葉。前は小さい 2 行だけだった。

## 5. D: 守ったもの

### 5.1 AppearanceOverrides（視差効果を減らす / 透明度を下げる / コントラストを上げる）

- **透明度を下げる**: M7 で足した面（`designCard()` のカード、バッジ）は
  `.quaternary` の塗りで、**ガラスではない**。したがって置き換えるべき自前のガラスが
  無い。ガラスはシステムの（サイドバー・toolbar・`.glassProminent`）だけで、これは
  macOS が自分で不透明に切り替える。**新しく足した塗りはすべて不透明**なので、
  この設定で見た目が壊れる余地が無い。
- **コントラストを上げる**: `designCard()` が 1px の縁を足す（`YakuGlass` と同じ考え方）。
- **視差効果を減らす**: 新しく足したアニメーションは、窓の高さの変更（`animate`）、
  スライダーの値（`contentTransition(.numericText())`）、ドロップ領域のホバーだけ。
  いずれも短く、`ProcessingGlowOverlay` は既存のまま `reduceMotion` を見ている。
- 3 つのデモフラグ（`--demo-reduce-transparency` / `--demo-increase-contrast` /
  `--demo-reduce-motion`）で設定と管理を起動し、落ちないことを確認した。
  **見た目は未確認**（ロック。撮影が要る）。

### 5.2 VoiceOver

- 新しく足した部品には名前を付けた: 向き（「英語 から 日本語」）、「詳細」、「読み込む」、
  「書き出す」、コピー（既存の「訳文をコピー」を維持）。
- バッジのアイコンは `accessibilityHidden(true)` にして、名前が文字だけになるようにした。
- **前後の比較はできていない**（ロック中は AX の木が窓を返さず、`axdump` が
  アプリ要素を辿ってしまう）。ロック解除後に
  `/tmp/axdump Yaku` を前後で撮って比べる必要がある。

### 5.3 ライト / ダーク

- 新しく足した色は**すべてシステムの意味の色**（`primary` / `secondary` / `tertiary` /
  `quaternary` / `accentColor` / `green` / `orange` / `red`）。ハードコードした色は
  足していない。したがってダークでも同じ規則で描かれる。
- **目視はできていない**（ロック）。

## 8. 親のレビュー

**合格**（2026-11-08 深夜）。画面ロックを解いて `tools/capture-m7.sh` で設定 12 枚と管理 12 枚を撮り、M2 の同じ構図と比べた。

親が直したもの:

1. **訳文ヘッダーの詰まり**: 「コピー」が窓の右端で切れ、処理時間の文（`2.42 秒 · PLaMo 0.8B · この Mac の中で処理`）が 2 行に折れていた。処理時間を訳文カードの下へ移し、原文側の「⌘↩ で訳す」と対にした（1 行、はみ出すときは中央を省略）。
2. **原文欄の空のスクロールバーの溝**: TextEditor は `.scrollIndicators(.hidden)` でも右端に溝が残る（M0/M2 から）。パネルと同じ縦長の TextField に替えた。
3. **右のペインが窓の外へはみ出す**（M2 から）: 翻訳と履歴の `HSplitView` は `NavigationSplitView` の中で、macOS 26 の浮いたサイドバーの余白を幅に入れない。サイドバーが ideal の 196 より細くなり、右のペインが約 15 pt 窓の外に出ていた（右の余白が 20 pt でなく 5 pt、履歴の空の案内が右へずれる）。`.ignoresSafeArea` では直らず、`HStack` + `Divider` に替えて直った。代わりにペイン幅のドラッグはなくなる（SPEC に要求はない）。翻訳は 2 ペイン等幅、履歴は一覧 320 pt 固定。

確認: `swift build`（debug / release）警告 0、`swift test` 221 件通る、管理 12 枚を撮り直して light / dark とも左右の余白が 20 pt でそろうことを目で確認。設定 6 タブ × 2 は今回の修正の外で、見出し・カード・説明がそろい、高さが内容に合っている。

まだのもの: VoiceOver の実画面での前後比較（コードの label と順序はテスト済み）。

## 9. 測り方（再現の手順）

```sh
cd app
swift build            # 警告 0
swift test             # 221 件
swift build -c release

# 窓の高さ（画面が要らない。ログを読む。ロック中は窓が画面外で winid の値が古くなる）
for tab in 一般 ショートカット エンジン PDF 画面翻訳 プライバシー; do
    .build/arm64-apple-macosx/release/Yaku --appearance light \
        --data-dir "$TMPDIR/yaku-m7" --demo-surface settings --demo-tab "$tab" \
        --demo-quit-after 20 >/dev/null 2>&1 &
    sleep 6
    grep 'settings: window ' ~/Library/Logs/Yaku/app.log | tail -1
    pkill -x Yaku
    sleep 1
done

# 撮影（**画面のロックを解いてから**）
swiftc -O tools/opaque.swift -o /tmp/opaque          # 一度だけ
tools/capture-m7.sh            # 全部（M7-settings-* 12 枚 + M7-manager-* 12 枚）
tools/capture-m7.sh settings   # 設定だけ
```

デモは必ず `--data-dir` で一時のフォルダに向ける（本物の履歴と PDF を汚さない）。
