### 1.1 パネルの中身（SPEC 4.2）

上から順に、上の帯（言語メニュー・入れ替え・文体・ピン・`ellipsis`）、原文の欄、区切り線、訳文、下の帯、すばやい操作の 6 つを実装した。

- 言語メニューは「自動（英語）→ 日本語」の 1 つの `Text` をラベルにしている。`Text` を複数並べたラベルは、SwiftUI が並べ替えたり切ったりしたため
- 文体の切り替え（である｜です・ます）は、目的の言語が日本語のときだけ出す。`GlassEffectContainer` と `glassEffectID` で形を引き継がせる
- 原文の欄は `TextField(axis: .vertical)`。M0 で見えていた `TextEditor` の常時スクロールバーはこれで消えた。高さは 1〜6 行で伸び、`TextMetrics` で測る（`onGeometryChange` で測ると自分の高さを書き換えて堂々巡りになった）
- 訳文は 15pt・行間 1.45 倍。`FadeInTextRenderer` で文字単位に描き、`.textSelection(.enabled)` で選べる
- 下の帯は `0.13 秒 · PLaMo 0.8B · この Mac の中で処理` と、コピーのボタン（押すと `checkmark` に変わり 1.2 秒で戻る）
- 4 つの状態（空・翻訳中・完了・エラー）は SPEC 4.2 の表どおり。エラーは赤の `exclamationmark.triangle.fill` と 13 章の文言、もう一度、ログを見る

### 1.2 光（SPEC 6.5）

**SwiftUI の `TimelineView` をやめて Core Animation にした。** これが M1 で一番効いた直し（4.1 を参照）。conic の `CAGradientLayer` を角丸の枠で切り抜き、勾配だけを回す。18px のぼかしは、太さと不透明度を変えた 8 本の枠で近似した（本物のぼかしは毎フレーム走らせると元のコストに戻るため）。

### 1.3 選択文の HUD（SPEC 4.3）

- ⌃⌥J で前面アプリの選択文を AX から取り、選択範囲のすぐ下（入らなければ上）に出す。位置が取れないときはマウスの位置
- 幅 420、高さは中身に合わせて最大 360。角丸 18 の `.regular` のガラス
- ⌥ を押している間は原文に切り替わる。下の帯に言語とコピー・置き換え・パネルで開く
- 選んだ文がないときは「文を選んでから ⌃⌥J」を 1.5 秒。許可がないときは「選んだ文を読むには、アクセシビリティの許可が必要です」と「システム設定を開く」

## 2. ビルド・テスト・起動の方法

```sh
cd projects/translate-app/app
swift build                 # 警告なし
swift test                  # 66 テスト / 10 スイート
./make-app.sh               # build/Yaku.app を作って署名
./make-app.sh install       # ~/Applications/Yaku.app に置く
```

画面を出す起動オプション（SPEC 15）。`--demo-pin` は、撮影中に誤ってクリックしても閉じないようにするために足した。

```sh
./build/Yaku.app/Contents/MacOS/Yaku --demo-surface panel --demo-state empty --demo-pin --demo-quit-after 40
./build/Yaku.app/Contents/MacOS/Yaku --demo-surface panel --demo-state translating --demo-pin --demo-quit-after 40 --demo-text "..."
./build/Yaku.app/Contents/MacOS/Yaku --demo-surface panel --demo-state done --demo-pin --demo-quit-after 60
./build/Yaku.app/Contents/MacOS/Yaku --demo-surface panel --demo-state error --demo-pin --demo-quit-after 40
./build/Yaku.app/Contents/MacOS/Yaku --demo-surface hud --demo-text "..." --demo-anchor 700,300 --demo-pin --demo-quit-after 45
./build/Yaku.app/Contents/MacOS/Yaku --demo-surface hud --demo-state no-permission --demo-pin --demo-quit-after 40
./build/Yaku.app/Contents/MacOS/Yaku --demo-surface panel --demo-glow 60 --demo-pin --demo-quit-after 90
```

`--demo-state translating` はキャッシュを迂回して同じ翻訳を繰り返すので、光の当たった状態を保てる（撮影と光の計測用）。

### 3.2 長文の分割（SPEC 7.4）

`--demo-surface panel --demo-state done` の見本は 1,939 文字の 3 段落。ログでは 4 つに割れて、前の 2 組を訳の履歴として渡している。

```
translate start id=... surface=panel chars=1939 chunks=4 source=en target=ja form=plain context=0ch
translate chunk 1/4 id=... chars=976 history=0
translate chunk 2/4 id=... chars=226 history=1
translate chunk 3/4 id=... chars=333 history=2
translate chunk 4/4 id=... chars=400 history=2
translate done id=... in 5.147s pairs=4
```

`history=2` で頭打ちになっているのは `PFML3.historyLimit` の 2 組までだから（SPEC 7.4）。画面では段落の間に空行が入った 3 段落として出る（撮影 3.4）。

### 3.3 順番と取り消し（SPEC 7.3）

訳している最中に 2 つ目の依頼を出すと、前のものが取り消され、新しいものだけが残ることをログで確認した。確かめるために、起動オプションの `--demo-state translating` に一時的に「2.6 秒後に別の文を訳す」細工を足して走らせ、終わったら元に戻した（仕様には残していない）。

```
translate start id=A47849CE surface=panel chars=1939 chunks=4 ...
translate chunk 1/4 id=A47849CE chars=976 history=0
probe: second request (different text)
translate: cancel panel request (new request on panel)
translate cancelled id=A47849CE
translate start id=ACB1DC37 surface=panel chars=51 chunks=1 ...
translate done id=ACB1DC37 in 0.286s pairs=1
```

- 前の依頼は `chunk 1/4` の途中で止まり、`chunk 2/4` は出ていない
- 新しい依頼は最初から通っている
- そのあとの `translate: cancel panel request` と `cache=hit` は、`--demo-state translating` が繰り返す性質によるもので、取り消しの動作そのものではない

### 3.4 エンジンが途中で落ちたときの立ち直り（SPEC 7.1）

自分で立てたエンジンにだけ `SIGTERM` を送って確かめた（`kill -TERM <engine pid>`。`pkill` や `killall` は使っていない）。

```
translate done id=FB971F65 in 4.958s pairs=4
engine exited unexpectedly pid=64317 status=0
translate start id=0751D39D ...
engine start pid=64609 port=54925 ...
engine ready pid=64609 in 1.68s
translate done id=0751D39D in 3.375s pairs=1
```

- 落ちたと気づいて、**1 回だけ**起こし直し、そのあとの依頼は通っている
- アプリを `kill` で終わらせたときにエンジンが残る場合も、次の起動で自分のものだけを止める:

```
stopping leftover engine pid=64609 port=54925
leftover engine pid=64609 stopped
engine start pid=65853 port=55037 ...
```

- 見分けは M0 と同じで、コマンド行に `llama-server` と自分のモデル・ポート・API キーが全部あるときだけ。親スレッドが動かしている別の `llama-server`（pid 96611）には最後まで触っていない

### 3.5 履歴とキャッシュ（SPEC 5.3、11）

`~/Library/Application Support/Yaku/Yaku.store`（SwiftData）に `ZHISTORYITEM` と `ZCACHEENTRY` の 2 つの表ができていることを `sqlite3` で確認した。M1 の確認中に 88 件の履歴と 4 件のキャッシュが入った。どちらも 5,000 件を超えたら古いものから捨てる。

キャッシュが効くこと（同じ文を 2 回）:

```
translate start id=3842BB7E surface=hud chars=33 ...
translate done id=3842BB7E in 1.700s pairs=1
translate start id=9BDE836F surface=hud chars=33 ...
translate done id=9BDE836F cache=hit in 0.005s
```

2 回目は 0.005 秒。エンジンを立てる時間も入らない。

### 3.11 人の操作が要るので未確認のこと

## 4. 仕様との違い・できなかったこと

### 4.1 CPU を 37% から 11% に下げた（残りは目標の外）

M1 で一番時間を使ったところなので、分かったことを残す。測り方は `tools/measure_cpu.py`（`ps -o %cpu` は起動からの平均なので使えない。プロセスの CPU 時間の差を窓で割る）。

**見つけた原因と直し方:**

1. **`TimelineView(.animation)` を `NSHostingView` の中で回していた。** 中身が `Color.clear` だけの `TimelineView` でも 9.2% 使っていた（フレームレートを 15fps に落としても 11.7% で、30fps の 13.2% とほとんど変わらない。毎フレームの再描画そのものが高い）。→ 光を Core Animation の `GlowLayerView` に置き換えた。**0.17%**。SwiftUI で書いた `ProcessingGlow.swift` は消した
2. **届いた断片ごとに `withAnimation` をかけ直していた。** 0.14 秒のアニメーションを新しい断片が来るたびに最初からやり直すので、SwiftUI が表示のフレームごとに描き直していた。**11.37%**（ぼかしを外して不透明度だけにしても 12.29% だったので、ぼかしは原因ではない）。→ 30Hz のタイマーで進める `TextRevealDriver` に置き換えた。**2.76%**
3. **`TextRevealDriver` の進む速さの計算が間違っていた。** 進む速さを「今回届いた分」だけで決めていたので、届く速さに追いつけず、854 文字の訳文に対して毎秒 10 文字でしか進まなかった。しかも進み切らないので 30Hz のタイマーが止まらず、**訳し終わったあともずっと回り続けていた**（これが「訳し終わった後の CPU」が 3〜5% あった本当の原因）。→ 「まだ出ていない残り全部」を 0.3 秒以内に出す速さに直した。**0.00%**
4. **届いた断片ごとに全文を出し直していた。** 訳文が伸びるたびに、パネルの文字をもう一度並べ直し、ガラスの下地（`NSViewUpdateVibrancyForSubtree` がサンプルに出ていた）まで巻き込んでいた。→ 一定の間隔に絞った。間隔ごとの実測は 33ms: 13.8%、66ms: 12.2%、100ms: **10.1%**。文字の出現は 30Hz なので、100ms にしても見た目は変わらない
5. **訳文の伸びに合わせて形の高さをアニメーションしていた。** 1 行伸びるたびに 0.16 秒のアニメーションをやり直すことになる。→ 訳している最中はアニメーションを外した（開くとき・状態が変わるときは今までどおり）

**残っている 11% の内訳（今の設定のまま、1 つずつ外して測った）:**

| 外したもの | CPU |
|---|---|
| 今のコード（3 段落 1,939 文字の翻訳中。100ms の間引き＋出現＋選択） | 11.6% |
| 文字の出現（`FadeInTextRenderer`） | 9.5% |
| 訳文の選択（`.textSelection`） | 11.4% |
| 届いた断片ごとの出版をやめる（出現だけ動かす） | **3.8%** |

**届いた断片ごとに訳文を出し直すこと自体が主なコスト**（11.6 → 3.8）。文字の出現が 2.1 ポイント、選択はほとんど効いていない。100ms の間引きで 11% まで来ている。これ以上下げるには、届いた段落だけを描き直すなどの作り替えが要る。**SPEC 14 章の目標には「訳している最中の CPU」の行がないので、今回はここまでとする。** 親スレッドの判断を仰ぎたい。

（「段落ごとに別の `Text` に分ける」「高さの書き戻しを外す」「スクロールバーを外す」も試したが、どれも 11% 前後で効かなかった。）

### 4.2 アクセシビリティの許可はまだ入っていない

計測中に一度「`accessibility trusted=true`」と出て、許可が入っていると読み違えかけた。**これは起動のしかたの違いだった。**

| 起動のしかた | `accessibility trusted` |
|---|---|
| 端末から `.build/.../release/Yaku` を直接起動 | `true`（起動元の端末の許可を引き継ぐため） |
| `~/Applications/Yaku.app` を Finder（`open`）から起動 | **`false`** |

インストールしたアプリを普通に使う場合の値は `false` なので、**⌃⌥J を押すと「選んだ文を読むには、アクセシビリティの許可が必要です」の HUD と、1 回だけの許可の案内が出る**（`selectionHotKey()` の分岐）。そこから先（許可をして選択文を取り、訳して置き換える）は人の操作が要る。

撮影した `M1-hud-no-permission-*.png` は `--demo-state no-permission` で出したものだが、実際の状態も同じ `false` なので、見た目は本物と同じ経路を通っている。

### 4.3 選択範囲のスクロールで HUD を閉じること

SPEC 4.3 は「HUD の外をクリック、前面アプリの切り替え、選択範囲のスクロールで閉じる」としている。外のクリックと前面アプリの切り替えは入れた。**選択範囲のスクロールは入れていない。** AX で選択範囲の位置を定期的に見に行く必要があり、その監視自体が CPU を使うため、M1 では見送った。

### 4.4 パネルの影

M0 から持ち越し。SPEC 4.2 の「影はシステムの窓の影」ではなく、SwiftUI の `.shadow` のまま（親スレッドが M0 のレビューで認めている）。

### 4.5 原文の欄のプレースホルダーの位置

プレースホルダーは `TextField` の標準の位置に出る。SPEC 4.2 が想定している位置と数ポイントずれている可能性があるが、撮影で見る限り読める。

### 4.6 すばやい操作の 3 つは動かない

「画面を翻訳 ⌃⌥O」「PDF を開く…」「履歴」は M4・M3・M2 の担当なので、M1 では見た目だけ（SPEC 18 章の段階分けどおり）。同じく、`ellipsis` メニューの「管理画面」「設定」も無効のまま。

### 4.7 エンジンが `status=0` で落ちたとき

`SIGTERM` で落としたときは `engine exited unexpectedly pid=... status=0` と記録される。正常終了のコードでも「自分が止めていないのに終わった」なら落ちたとみなす、という判定にしている（`stoppingIntentionally` で見分ける）。

## 5. M2 に向けて気づいたこと

- **訳している最中の CPU が 11%**（4.1）。目標の表には行がないが、M5 で仕上げるときに効いてくる。届いた段落だけを描き直す作りにすると下がる見込み
- **0.8B は文脈と用語集がないと弱い**（M0 から持ち越し）。M1 では文脈（前面アプリ名・窓のタイトル・前後 200 字）と訳の履歴（前 2 組）を渡すところまで作った。**用語集は M2**なので、「Attention」→「注意」はまだ直らない
- **キャッシュのキーに用語集と文脈が入っている**ので、M2 で用語集が変わるとキャッシュは自然に外れる
- **`TextRevealDriver` の進む速さ**は、訳文が長いときに 0.3 秒で出し切るようにしている。段落が増えると少しせわしなく見えるかもしれない
- 履歴が 88 件たまった。M2 の履歴の画面では、入口（パネル / HUD）と日時で並べられる形にしてある
- **許可がまだ入っていない**（4.2）。インストールしたアプリで ⌃⌥J を押すと許可の案内が出るので、**M1 の完了条件（Safari・メモ・VS Code の 3 つで ⌃⌥J → 訳 → 置き換え）の実地の確認は親スレッドで**。人が許可を出したあと、この 3 つで確かめてほしい
