# PLaMoの利用条件確認メモと問い合わせ下書き

[公開までのタスク](release-tasks.md)のR04で使う確認資料です。
個人開発・無料・収益化なしで、まずGitHubにソースだけを公開する計画です。
ビルド済みアプリの配布は後日に分けます。
登録状況と規約上の適用区分は未確認で、問い合わせも送信していません。
ソース公開そのものに商用登録が必須と判断した資料ではありません。
モデルの実行や出力の共有に関する確認メモとして残し、送信は保留しています。
以下の下書きは、配布者が内容と送信先を確認してから使います。

## 公式に確認できたこと

2026-11-13に、次の公式案内を読みました。
規約の改訂日は2026-11-09です。以下の説明は規約本文の代わりにはなりません。

| 資料 | 確認できた内容 |
|---|---|
| [PLaMo Community License](https://plamo.preferredai.jp/info/plamo-community-license-en) | 第1条の商用目的には製品・サービスの開発や提供、組織内での利用も含まれる。第3条では商用利用の事前登録と年収入・売上の条件を定めている |
| [商用利用登録フォーム](https://forms.gle/mTL8tBLrMYXKNZD56) | 条件を満たす場合は、用途を書いて送信した時点から商用利用できるとの案内がある。フォーム入力にはGoogleへのログインが必要 |
| [PFNのお問い合わせ案内](https://www.preferred.jp/ja/contact/) | 「ビジネスについてのお問い合わせ」からプロダクト利用に関する問い合わせができる。登録フォームも、10億円を超える場合の問い合わせ先として案内している |

無料で公開することだけでは、個人利用に当たるとは確定しません。
年収入・売上の条件は、規約とフォームに従って配布者自身が確認します。
フォームでは、関係会社がある場合のグループ全体の収入・売上についても記載があります。
勤務先との関係などで判断がつかない場合は、推測で区分を選ばずPFNへ確認します。

## 配布者が確認すること

公開リポジトリには、氏名、連絡先、登録回答、契約書、詳しい収入を記入しません。
必要な確認結果だけをタスク表へ残し、原本は配布者が非公開で保管します。

| 項目 | 現在の状態 | 確認方法 |
|---|---|---|
| 配布・モデル利用の主体 | 個人開発のプロジェクト（配布者の回答） | 規約上の利用区分とは区別する |
| 無料・有料、寄付・広告・課金の予定 | 無料、寄付・広告・課金なし（配布者の回答） | これだけで商用区分を決めない |
| 公開先と公開物 | まずGitHubのpublicリポジトリでソースのみ公開。ビルド済みアプリの配布は後日 | 今回の確認と後日の配布準備を分ける |
| 既存の登録と別契約 | 未確認 | 配布者自身が登録フォームの回答控えや契約を確認する。アプリの規約同意とは区別する |
| 関係会社を含む収入・売上の適用範囲 | 未確認 | 公式条件と契約主体を照合し、不明ならPFNへ問い合わせる |
| エンドユーザー向けの登録案内 | 未確認 | 配布者の登録が利用者全員を対象にするとは扱わず、PFNへ確認する |

商用利用の条件に該当する場合、登録は公開直前だけの手続きとは限りません。
開発中のモデル利用も含めて確認し、未登録のまま続けてよいとは判断しません。
個人情報の入力、登録、契約への同意、問い合わせの送信には、配布者の別途承認が必要です。

## 問い合わせ下書き

送信前に、角括弧の未確認欄を配布者が埋めます。
氏名・連絡先は送信先のフォームで入力し、このファイルには追記しません。

### 件名

PLaMo 3 Translateを使うローカル翻訳アプリの利用条件・出力通知について

### 本文

Preferred Networks ご担当者様

macOS向けのローカル翻訳アプリ「Perspica」の公開を準備しています。
PLaMo Community License（2026年11月9日改訂）の適用について確認したく、ご連絡しました。

個人開発のプロジェクトで、GitHubのpublicリポジトリで公開する予定です。
無料公開で、寄付・広告・課金は行いません。
まずソースコードだけを公開し、ビルド済みアプリの配布は後日に分けます。
商用利用の登録履歴・別契約の有無は［配布者が記入］です。
収入・売上の適用条件については［確認済みの区分、または判断が必要な事情を配布者が記入］です。

アプリは、選択した文章、入力した文章、画面上の文章、PDFをMac内で翻訳します。
PLaMo 3 TranslateのGGUFをllama.cppのローカルサーバーで実行し、
翻訳する原文・訳文を外部へ送信しない構成です。

現在の配布構成では、モデルをアプリに同梱せず、
利用者が管理画面からPFNのHugging Faceリポジトリにある
PLaMo 3 Translate 0.8B・2B・8BのQ4_K_M GGUFを別途取得します。
手元のモデルファイルを指定する経路もあります。
アプリ側では、規約全文の同梱・新規ダウンロード時の同意と、
「Built with PLaMo」の表示を実装しています。
既存モデルへの改訂案内と、出力を渡す際の通知は対応を検討中です。

以下の4点をご教示いただけますでしょうか。

1. 上記の利用・配布形態は、第1条・第3条の商用目的に当たりますか。
   必要な登録・契約の主体と、関係会社を含む収入・売上の確認範囲を教えてください。
   利用者が業務で翻訳する場合、その利用者にも別途登録が必要でしょうか。
2. 利用者がPFNのリポジトリからモデルを取得する構成は、第4条ではどのように扱われますか。
   アプリとモデル取得画面に必要な規約・表示・案内に、不足があれば教えてください。
3. 第5条第4項の通知は、コピーした文章、テキスト保存、翻訳PDFについて、
   どのような方法なら受領者に認識できる通知として扱われますか。
   本文と別の通知ファイル、PDF内の通知ページ、短いライセンスURLなどを検討しています。
   アプリ利用者への表示だけで通知が済むとは考えていません。
   第5条第2項の書籍・論文などの長文刊行物に関する表示とは、区別して対応したいと考えています。
4. 後日のビルド済みアプリ配布では、アプリ本体（MITライセンス）にモデルを同梱せず、
   利用者がPFNのリポジトリからモデルを取得する構成を予定しています。
   モデル資料にはPLaMoの条件をそのまま適用します。
   このようにモデルを別途取得する構成について、PLaMoの条件上、追加の許諾や制約はありますか。

よろしくお願いいたします。

## 回答後に残す記録

回答日、対象となる規約の版、確認した構成、許可・条件・未回答事項を整理します。
回答の引用や公開には、その回答の取り扱い条件も確認します。
登録が必要な場合は、登録主体、対象用途、送信日、控えの保管先を非公開で記録します。
問い合わせを送っただけでは、R04を完了にしません。廃止したAGPL対応のR03とは別に扱います。

通知方法は回答を踏まえてR08〜R10へ反映し、実装と実アプリでの検証は別に行います。
